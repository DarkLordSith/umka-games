# Умка

Личное PWA с логическими играми для сына владельца (4 года). Играет на iPhone (свой и мамин), установка «На экран Домой» из Safari. Магазина, рекламы и покупок нет.

Владелец — джун-фулстак. Он ставит задачи, тестирует с сыном и мерджит PR. Код пишешь ты. Объясняй решения коротко и по-русски: что сделал и зачем. Выбирай инструмент, который подходит задаче, а не «лишь бы работало».

## Игрок
- 4 года, не читает, только начал изучать числа.
- **Сильнее, чем кажется.** В Food Hunt (муравьи) с помощью родителей дошёл примерно до 100-го уровня, в Color Jam — до 73-го, часть уровней решал сам. В Color Jam ему мешал в основном **таймер**, а не сама задача.
- Проигрыш переносит спокойно и переигрывает. Экрана «проиграл» у нас всё равно нет: вместо него Undo.
- В муравьях цепляет **процесс поедания**, а не сложность картинки.
- Вывод: стартовая сложность — не «самое лёгкое», а средняя; дальше её подстраивает адаптивная сложность.

## Принципы для всех игр
- **Ни одного слова текста** в детской части: иконки, цвет, озвучка, анимация-подсказка («рука показывает, куда тянуть»). Текст можно только в родительском экране за родительским замком.
- **Без давления:** без таймеров, жизней, монет, рекламы и покупок. Undo без ограничений. В тупике пульсирует кнопка «назад». Кнопка «заново» маленькая, в углу.
- **Адаптивная сложность:** 3 уровня подряд без подсказки → сложнее; застрял → проще. Логика в `engine/difficulty`, не в играх.
- **Крупные цели касания:** от 60 pt; зона захвата при перетаскивании больше видимого объекта.
- **Награда за уровень:** анимация, звук, голос и наклейка в альбом (1 пройденный уровень = 1 наклейка). Прогресс видно без цифр — по заполненному альбому.
- **Защита от случайного выхода:** выход в меню долгим нажатием на кнопку-домик в углу.
- **Совместная игра с родителем** — часть пользы: интерфейс не мешает проговаривать «угол», «слева», «подходит».

## Визуал и звук
- Яркий мультяшный «конфетный» стиль: крупные формы, мягкие тени, сочные цвета. Пиксель-арт — только в игре с муравьями.
- Всё живое: блок сплющивается при ударе, муравьи бегут цепочкой, конфетти на победе.
- Звук: короткие приятные эффекты (Web Audio) и голос. Голос — файлы `public/voice/<id>.m4a` (`docs/VOICE.md`): сейчас заглушка голосом Milena из macOS, потом записи владельца подменяют файлы без правок кода. Синтез речи в браузере (`speechSynthesis`) не используем. Постоянной музыки нет.
- Графика — своя (код, SVG) или CC0 с источником в `README` рядом с файлом. Арт, звуки и уровни оригинальных игр не берём. Медвежонка Умку из мультфильма не рисуем: название — просто слово.
- Игровые цвета — из одной палитры (`src/ui/palette.ts`), не больше 8, хорошо различимые между собой. Цветовые литералы вне палитры — ошибка теста.

## Стек
- **React + TypeScript (strict) + Vite.** Версии — актуальные стабильные на момент установки, в `package.json` точные (без `^`).
- **vite-plugin-pwa** (Workbox) — манифест и service worker. Ручной `sw.js` не пишем.
- **Vitest** — логика, генераторы, решатели, прогресс.
- Анимации — CSS и Web Animations API. Библиотеку (например, `motion`) подключать, только если CSS не справляется; причину написать в отчёте.
- Canvas — там, где DOM не тянет по производительности (вероятно, муравьи; решается в задаче экрана).
- Без бэкенда, аналитики и внешних CDN: всё работает офлайн.
- Деплой: GitHub Actions → GitHub Pages, `base: '/umka-games/'`.

## Команды
- `npm run dev` — разработка.
- `npm run build` — сборка в `dist/`.
- `npm run preview` — проверка сборки, в том числе PWA и офлайн.
- `npm test` — Vitest.
- `npm run typecheck` — `tsc --noEmit` для приложения, конфига/скриптов и тестов.
- `npm run icons` — перегенерировать иконки PWA.

## Структура
> План. Поддерживай раздел в актуальном виде, когда меняешь структуру.

- `src/main.tsx` — вход, регистрация service worker.
- `src/app/storage.ts` — единственное место с `localStorage`: загрузка/сохранение прогресса, копия битого в `umka-progress-broken`. В dev `?level=N` открывает любой уровень.
- `src/app/base.css` — базовые стили и iOS-защиты (safe-area, верхняя зона `.sky`, без зума и «резинки»); `src/app/ios.ts` — гашение щипка и двойного тапа.
- `src/app/` — оболочка: меню, экран игры (`GameHost.tsx` — сессия, сложность, награда), альбом, родительский экран. Только она трогает хранилище и решает, какой экран показан.
- `src/engine/` — **чистый TypeScript без React и DOM:** контракт игры (`types.ts`), история и Undo (`history.ts`), сессия уровня (`session.ts`), адаптивная сложность (`difficulty.ts`), сидируемый генератор случайных чисел (`rng.ts`), прогресс и миграции (`progress.ts`).
- `src/audio/` — эффекты (`sfx.ts`), голос (`voice.ts`, список фраз `phrases.ts`), разблокировка звука первым касанием.
- `src/rewards/` — наклейки (генерация SVG), конфетти, альбом.
- `src/ui/` — общие компоненты (крупная кнопка, долгое нажатие, рука-подсказка) и палитра.
- `src/games/<id>/` — модуль игры: `index.ts` (`GameModule`), `logic.ts`, `generator.ts`, `solver.ts`, `Screen.tsx`, свои ассеты. У муравьёв ещё `render.ts` — canvas-слой (картинка и муравьи), DOM — колонки, слоты, кнопки. `src/games/registry.ts` — список игр в меню.
- `public/voice/` — записи голоса, `<id>.m4a`.
- `public/icons/` — иконки PWA, генерирует `npm run icons` (`scripts/icons.ts`, SVG → PNG через resvg, цвета из палитры).
- `tests/` — Vitest (свой `tests/tsconfig.json` с типами Node); `tests/fixtures/` — сохранённые прогрессы прошлых версий.

## Контракт игры
Задан в `src/engine/types.ts` (задача engine/core). Если меняешь контракт — обнови этот раздел.

```ts
interface GameModule<State, Move> {
  id: string;                                         // 'ants', 'color-jam' — ключ в прогрессе
  Icon: ComponentType;                                // иконка в меню, без текста
  startDifficulty: number;                            // с чего начинает новый игрок
  minDifficulty: number;                              // ниже адаптивная сложность не опускается
  makeLevel(difficulty: number, seed: number): State; // детерминированно: тот же (difficulty, seed) → тот же уровень
  applyMove(state: State, move: Move): State | null;  // null — ход невозможен; state не мутирует
  isWon(state: State): boolean;
  isStuck(state: State): boolean;                     // к победе не пройти → пульсирует Undo
  hint(state: State): Move | null;                    // следующий ход решателя
  Screen: ComponentType<GameScreenProps<State, Move>>;
}

interface GameScreenProps<State, Move> {
  state: State; start: State;                         // текущий и стартовый снимки
  won: boolean; stuck: boolean; canUndo: boolean;
  onMove(move: Move): boolean;                        // false — ход невозможен
  onUndo(): void; onRestart(): void;
  onWinShown(): void;                                 // экран доиграл свою анимацию победы
}
```

Кто что делает:
- **Оболочка** (`src/app/GameHost.tsx`) ведёт сессию уровня (`engine/session.ts`: история, ходы, подсказки, «был тупик»), адаптивную сложность (`engine/difficulty.ts`), прогресс и награду. Победа сохраняется сразу: новая сложность и `seed + 1`.
- **Экран игры** только показывает `state` и зовёт `onMove`. Своё изменение он узнаёт по ходам, которые сам отправил; любое другое (Undo, «заново») показывает мгновенно.
- Уровень = `(difficulty, seed)`. Сложность меняет адаптация, `seed` растёт на 1 с каждой победой — так на одной сложности уровни всё равно разные.

Правила:
- Логика игры — чистые функции над неизменяемыми снимками. На этом держится Undo: история — это просто массив снимков.
- Игры не импортируют друг друга. Общее — только `engine/`, `ui/`, `audio/`, `rewards/`.
- Игра не трогает `localStorage` и не решает, что такое победа для приложения: она отвечает на `isWon`, а награду, голос и следующий уровень делает оболочка.
- Звук и голос экран игры просит через хук из `audio/`, а не создаёт `AudioContext` сам.

### Новая игра
1. Папка `src/games/<id>/` с `GameModule`.
2. Строка в `src/games/registry.ts`.
3. Тесты: логика, генератор (каждый выданный уровень решаем), решатель.
4. Иконка в меню.

Уровни **не рисуются руками**: их выдаёт генератор, решатель проверяет решаемость и меряет сложность. Число уровней ограничено только кривой сложности.

## Прогресс: не ломать
- Ключ `localStorage`: `umka-progress`. В объекте поле `v` — версия схемы.
- Новое поле → значение по умолчанию в `migrate()`. Переименование или удаление → преобразование в `migrate()`.
- Битый JSON → чистый прогресс без падения; старое значение копируется в `umka-progress-broken`.
- В `tests/fixtures/` — прогрессы прошлых версий, тест обязан загружать каждый.
- Ничего личного в прогрессе не храним.

## UI и iOS
- iPhone в портрете. Проверяем на 375×667 (SE) и 390×844 (iPhone 12/13).
- `viewport-fit=cover`, safe-area через `env(safe-area-inset-*)`.
- **Урок «Тёмного прилавка»:** в установленной PWA верх экрана примерно до 80 pt размыт под статус-баром. Там только фон и декор, никаких кнопок и важной графики.
- Запрет зума и «резинки»: `user-scalable=no`, `touch-action: none` на игровом поле, `overscroll-behavior: none`, `user-select: none`, `-webkit-touch-callout: none`.
- Звук стартует только после первого касания (браузеры не дают раньше).
- Service worker: `skipWaiting` + `clientsClaim`, страница сама перезагружается на новую сборку; при возврате PWA на экран — проверка обновления.
- Без `alert`, `confirm`, `prompt` — только свои модалки.
